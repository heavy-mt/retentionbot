# Работа с Retentionbot

## Начало работы

1. Прочитать docs/index.md, docs/architecture.md и docs/development.md.
2. Проверить фактический Git SHA, изменения рабочего дерева и конфигурацию CI.
3. Найти относящиеся к задаче исходники и тесты. Документы описывают намерение,
   текущие интерфейсы проверять по коду. Не выдумывать пути API или возможности клиента.

## Инварианты

- Native retention Synapse остаётся включённым. Redaction, физический purge и
  очистка клиентского кэша — три разных этапа; не объявлять один доказательством другого.
- Observer/worker получают только метаданные; не добавлять тела, ciphertext,
  ключи E2EE или пользовательские Matrix-токены в их БД/логи/RabbitMQ.
- Command-bot — обычный пользователь, только личные чаты. Не выдавать ему
  модульный master secret, доступ к broker/state сети или членство в целевых комнатах.
- Права проверяются сервером по фактическому событию команды, не по actor_id
  из неподтверждённого входа. Учитывать снятие прав после выбора комнаты.
- Cutoff и курсор учёта постоянны. Не сбрасывать их при рестарте/обновлении.
- Обычная redaction продолжается от текущего DAG. Историческая ветка допустима
  только как ограниченный fallback после отказа; сохранять room limiter и purge lock.
- Сообщения RabbitMQ доставляются повторно. Действия идемпотентны; pending
  не удаляется compaction. Synapse подтверждает очистку раньше локального удаления.
- SQL-параметры привязаны. Не выполнять TRUNCATE истории или очистку по принципу
  «события уже нет» без анализа назначения таблицы.

## Документы и проверка

- Пользовательский текст хранить в docs/user-guide.md. Не включать туда детали
  реализации. Архитектуру, API, БД, миграции и ограничения менять в технических документах.
- Обновлять CHANGELOG при изменении поведения. Не отмечать живой сценарий
  пройденным на основании CI; отдельно фиксировать локальные skips и полное CI.
- После функциональных изменений запускать относящиеся тесты и Ruff; финальный
  релизный коммит проходит полный CI с настоящими Synapse/PostgreSQL/RabbitMQ и Docker.
- Не повторять уже принятую клиентскую матрицу без изменения deletion/reset поведения.
- Не публиковать токены/пароли и не коммитить secrets, runtime или локальные override.
- Сохранять том command-bot-data при обновлении: он содержит ключи и диалоги.

Проверенный стенд описан в docs/operations.md. Поддержку других версий Synapse,
клиентов и topology не выводить из нижнего ограничения версии пакета.
