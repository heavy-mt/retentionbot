# Проверка на стенде и телефонах

Записать версии Synapse, Element X Android/iOS и дату. Использовать отдельные тестовые
аккаунты и свежие файлы. До пилота проверить включение бота и ошибки всех комнат.

| Проверка | Ожидаемый результат |
| --- | --- |
| Существующая приватная комната | Бот приглашён, вступил, получил права redaction; старая история сохранена |
| Новая комната, включая личную | Бот подключён после очередного сканирования; начало обработки видно в статусе |
| Команда обычного участника | Срок сохраняется, бот сообщает об отсутствии прав |
| Команда администратора | Срок изменён, получено подтверждение |
| Разные min/max двух комнат | Сообщения каждой комнаты удаляются по её сроку |
| Увеличение/отключение после постановки задачи | Ожидающий worker повторно проверяет политику и сохраняет сообщение |
| Текст при открытом Element X | После срока и синхронизации содержимое исчезает |
| Комната не открывалась | При открытии просроченное содержимое становится недоступным |
| Редактированное сообщение и реакции | Исходное сообщение, редакции и реакции обработаны по исходному сроку |
| Файл/фото/видео/голосовое | Содержимое сообщения удалено; локальный файл после паузы недоступен на сервере |
| Один файл в двух комнатах | Файл сохраняется до удаления последней учтённой ссылки |
| Повторная доставка задачи | Повторная redaction не создаётся после зафиксированного успеха |
| Перезапуск observer/worker/RabbitMQ/PostgreSQL | Настройки и ожидающие задачи сохранены, обработка продолжается |
| Пропуск более 100 событий observer | Доступная история восполнена; при уже выполненном purge ошибка видна, новые события продолжают обрабатываться |
| Недоступный ключ E2EE | Redaction по ID выполняется по сроку; поиск файлов ждёт ключа, физическая очистка приостановлена |
| Телефон выключен на срок меньше max_lifetime | После возврата и синхронизации содержимое удалено |
| Телефон выключен дольше TTL, активная комната | Проверить очистку старого локального кэша после возврата |
| Долгий офлайн и неоткрытая комната | Проверить исчезновение содержимого при открытии без перелогина |
| min/max и серверные границы | Длительности проверены, max приведён к границам Synapse, минимум соблюдён |
| Слишком узкое окно, min=max | Ошибка настройки, обещания доставки перед purge нет |
| Бот успел до native purge | Redaction доступна клиентскому API и приходит в sync, штатная очистка продолжает работать |
| Native purge успел первым | REDACTION_NOT_VISIBLE, задача не считается успешной |
| JSON-команды и ответы | Понятные JSON-объекты, изменение политики действительно записано в m.room.retention |
| Прикладные логи | Один корректный JSON на каждую физическую строку, без токенов и текстов сообщений |
| Доступ к RabbitMQ | Observer/worker подключаются; gateway и сторонние контейнеры не имеют сети брокера; внешних портов нет |
| PostgreSQL в Compose | Версия 18.6, постоянный том, app-пользователь не superuser, внешнего порта нет |
| Нагрузочный пилот | Измерены скорость удаления, рост очереди, E2EE, I/O и объём БД на заявленном потоке |

Для короткого теста задать JSON-командой короткие min/max в рамках серверных границ и уменьшить
REDACTION_LEAD_SECONDS в тестовой установке. Штатный retention остаётся включённым.
Изменение времени БД в автоматических тестах применяется только к изолированным данным.

Успешный PUT redaction сам по себе не доказывает доступность удаления для клиента.
Worker также проверяет его клиентским API. Поведение Element X подтверждается
визуально на обоих телефонах. Зафиксировать фактические задержки, вид отметки об удалении и
результат длинного офлайна. До этих проверок клиентская приёмка остаётся открытой.
