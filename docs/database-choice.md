# База данных серверной службы

Для заявленного устойчивого потока **более 100 сообщений/с** основная поставка использует
PostgreSQL 18.6, Docker-тег `postgres:18.6-bookworm`. Это отдельная БД метаданных службы.
База Synapse продолжает работать со своей конфигурацией.

Само число 100 сообщений/с не является пределом SQLite. SQLite с WAL может справиться
с таким потоком на одной машине, особенно при коротких транзакциях и пакетных записях.
PostgreSQL выбран из-за предполагаемого длительного потока, нескольких worker,
размеров активных данных и независимого обслуживания БД.

При постоянных 100/с получается 8,64 млн событий в сутки и 60,48 млн за семь дней.
Кроме незавершённых событий, версия 0.3 хранит успешные результаты ещё семь дней.
После этого она удаляет их пакетами. Пропущенные и незавершённые задания остаются
для разбора. План диска должен учитывать индексы, WAL, резервные копии и эти результаты.

| Условие | SQLite | PostgreSQL |
| --- | --- | --- |
| Одна машина, умеренный поток | Подходит | Подходит |
| Несколько пишущих процессов | Один writer одновременно, нужны короткие транзакции | Параллельные записи и блокировки строк |
| Несколько Docker-хостов | Общий SQLite WAL на сетевой ФС не подходит | Сетевой доступ к серверу БД |
| Десятки миллионов событий | Возможно, требуется проверка диска и блокировок | Основной выбранный вариант |
| Эксплуатация | Постоянный локальный том и согласованные копии | Отдельный том, роль, pg_dump и мониторинг |

В основной Compose порт PostgreSQL наружу не опубликован. Роль `retention` создаётся
без superuser, CREATEDB и CREATEROLE. Метаданные версии 0.3 находятся в схеме `server`.
Том PostgreSQL 18 смонтирован в `/var/lib/postgresql`.

Альтернатива SQLite: отсутствие `DATABASE_URL`, постоянный `/data/server.db`,
общий локальный том observer/worker, один Docker-хост. Основной Compose использует
PostgreSQL; для SQLite нужно изменить deployment-конфигурацию.

Бот личных команд имеет отдельный небольшой SQLite WAL в постоянном Docker-томе.
Он хранит выбор комнаты, позицию sync и исходящие ответы. Эти данные не связаны
с потоком всех сообщений сервера: их записывает один процесс, поэтому отдельный
PostgreSQL или доступ к БД планировщика ему не нужен.

Выбор БД не подтверждает производительность всей цепочки. На стенде проверяются
Synapse API, работа внутренних обработчиков, очередь, отставание observer,
задержка redaction и диски. Функциональные тесты CI повторяются на SQLite и PostgreSQL.
