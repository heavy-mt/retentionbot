# Очистка метаданных 0.3.1

Observer удаляет завершённые задания `done` и `missed` порциями до 1000 записей.
И событие, и связанная инвалидизация должны быть завершены более семи суток назад.
`pending`, неизвестное время завершения и неизвестное поколение инвалидизации
сохраняются. Старые завершённые события без связанной инвалидизации также очищаются.

Порядок очистки:

1. Observer выбирает подходящие записи в своей БД.
2. Через защищённый API `/internal/compact-invalidations` передаёт Synapse
   event_id, room_id, generation и completed_at.
3. Synapse проверяет возраст подтверждения, совпадение поколения, отсутствие
   исходного события и наличие сохранённой очереди сброса кэша, если reset включён.
   Затем удаляет только подтверждённые строки `retentionbot_event_invalidations`.
   Поколения комнат, устройств и пользователей не удаляются.
4. Только после ответа `done` observer повторно проверяет подходящие локальные
   записи и удаляет именно подтверждённую порцию. Связанные инвалидизации удаляются
   по внешнему ключу `ON DELETE CASCADE`.

При недоступном или старом модуле Synapse записи сохраняются; scheduler повторяет
попытку. Обновлять нужно сначала Synapse, затем observer/worker. Потеря ответа после
удаления строк Synapse безопасна: повтор подтверждения принимает отсутствующие строки.
Повторная доставка RabbitMQ не вызывает API для завершённого или удалённого задания.

Семь суток — окно хранения подтверждений, не обещание вечной дедупликации.
При восстановлении более старого бэкапа retention-БД или ручном вызове invalidate
для уже очищенного event_id возможно новое поколение и дополнительный сброс кэша.
Это не восстанавливает удалённые сообщения. Бэкапы обеих БД и cutoff следует
восстанавливать согласованно. Не удаляйте таблицы и не перематывайте observer cursor
в качестве обычного обслуживания.

Очистка охватывает подтверждения, для которых сохранились задания observer.
Строки, потерявшие такую связь до обновления или при несогласованном восстановлении,
автоматически не удаляются: требуется отдельная сверка. Незавершённые задания могут
накапливаться при длительной неисправности; следите за их возрастом и количеством.

`stream_ordering_to_exterm` — отдельный исторический кэш DAG Synapse. Исправление
ветвления не удаляет старую историю. Штатная очистка использует окно около 30 суток.
Исторические снимки нельзя удалять только потому, что исходные события уже purged.

PostgreSQL использует освобождённые страницы повторно. Обычная очистка и VACUUM
не обязаны уменьшать размер файлов на диске. Старые 1.7 ГБ — отдельная задача
обслуживания после штатной очистки, а не повод выполнять TRUNCATE.
