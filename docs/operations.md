# Установка, обновление и обслуживание 0.3.1

## Новая установка

Следуйте [README](../README.md#установка-в-существующий-synapse) и
[примеру конфигурации](../deploy/synapse-module.yaml.example).
Проверенная версия — Synapse 1.162.0; образ проекта включает оба патча Synapse.
Не заменяйте его штатным образом без повторной проверки совместимости.
Сохраните существующие signing keys, конфигурацию, БД и медиа Synapse.
Модульный секрет и cutoff должны находиться на постоянном томе; каталог secrets
закрыт для посторонних. Cutoff нельзя генерировать заново при обновлении.

Compose требует существующую Docker-сеть Synapse и переменные SYNAPSE_URL,
SYNAPSE_NETWORK, DATABASE_PASSWORD, RABBITMQ_PASSWORD. В чужом Compose-проекте
имя postgres может конфликтовать; задайте уникальный адрес retention-БД через
локальный compose.override.yaml. Не включайте токены и override с секретами в Git.

Для command-bot используйте обычную локальную учётную запись без прав администратора
сервера. Сохраните токен в secrets/command_bot_access_token и задайте
COMMAND_BOT_USER_ID. Постоянный command-bot-data сохраняет ключи E2EE и выбранные
комнаты. Бот управляет сроком по правам отправителя и не вступает в целевые комнаты.

## Обновление с 0.3.0

1. Сохраните дампы обеих PostgreSQL БД, конфигурацию, secrets, cutoff и том
   command-bot-data. Запишите текущий Git SHA и имена образов для отката.
2. Переключите checkout на проверенный релизный коммит. Сохраните локальный
   compose.override.yaml. Соберите образы до остановки действующих служб.
3. Соберите deploy/Dockerfile.synapse из этого checkout и обновите Synapse через
   его фактический механизм развёртывания. Его контейнер может не принадлежать
   Compose retentionbot. Сохраните все тома, сети, параметры и секреты.
4. После восстановления health Synapse обновите observer, worker и command-bot.
   Ни RabbitMQ, ни PostgreSQL для этого обновления пересоздавать не требуется.
   Пример для четырёх worker, из каталога проекта:

   ```bash
   (
       set -euo pipefail
       docker compose --profile commands build observer worker command-bot
       docker compose --profile commands up -d --no-deps --scale worker=4 \
           observer worker command-bot
       docker compose --profile commands ps
       docker compose exec -T observer retentionbot status
   )
   ```

5. Проверьте версии установленных пакетов, очереди, ошибки scheduler и команду
   «Статус» в существующем личном чате. Очистка старых метаданных начнётся, когда
   обе даты завершения выйдут за семидневное окно. Немедленное уменьшение размера
   файлов PostgreSQL не является критерием успешного обновления.

При откате сохраняйте cutoff и данные. Обновление не меняет схему таблиц Synapse.
Откат observer прекращает согласованную очистку; старый observer очищает только
done, поэтому длительно оставаться на нём не следует. Восстановление БД из бэкапа
требует согласования состояния обеих БД; возможны дополнительные cache-reset.

## Контроль работы

- Проверяйте health observer, Synapse и command-bot, свежесть last_poll_at,
  возраст pending и причины blocked/missed. EVENT_PURGED означает, что native
  purge опередил redaction; отдельно проверяйте завершение инвалидизации.
- В RabbitMQ контролируйте ready, unacked, consumers и dead queue. Нулевая очередь
  сама по себе не доказывает отсутствие отложенных заданий в БД.
- Для очистки проверяйте количество старых terminal-заданий и строк Synapse
  retentionbot_event_invalidations. Ошибки COMPACTION_UNCONFIRMED сохраняют
  метаданные для повторной попытки.
- Различайте текущие forward extremities и исторические снимки. На исправленной
  нагрузочной комнате tips_max=1 и одна строка на снимок; старые ветвящиеся снимки
  остаются до штатной очистки.
- Планируйте место для семи суток метаданных заданий и около месяца исторического
  кэша Synapse. Размер зависит от потока событий и состояния очередей.
- Медиа имеет отдельную политику: redaction/purge события не обещает удаления
  файлов и миниатюр по тому же сроку.

## Границы проверенного релиза

Проверены одиночный Synapse 1.162.0, PostgreSQL 18.6, RabbitMQ 4.3.6,
четыре retention-worker и Element X Android. Несколько процессов Synapse,
внешние Synapse workers и iOS требуют собственной проверки перед развёртыванием.
Не обещается ровно 100 msg/s или удаление без задержки. При перегрузке очередь
догоняет; на стенде все сообщения в проверенных sustained-прогонах были purged,
инвалидизации завершены. См. историю [нагрузочных тестов](loadtest-2026-10-09.md).

См. [порядок очистки метаданных](metadata-compaction.md) перед ручным обслуживанием.
