# Автоудаление Matrix / Element X

Черновик рамок решения для согласования, версия 0.1.0.

## Цель

Содержимое новых сообщений становится недоступным в Element X после синхронизации без
выхода из учётной записи и повторного входа. Вложения управляемого Synapse физически удаляются
с сервера после удаления последней учтённой ссылки.

## Работа службы

- Бот подключается ко всем обычным комнатам с локальными участниками, включая приватные
  и личные переписки, при наличии прав. Ошибки подключения видны администратору сервера.
- Старая история ботом не обрабатывается. Начало — успешное подключение к комнате.
- Текст, файлы, редакции и реакции обрабатываются, в том числе в зашифрованных комнатах.
- Штатный retention Synapse остаётся включённым. Бот читает его реальные настройки и политики
  комнат; команды администратора меняют обычную политику комнаты через Matrix API.
- Настройки задаются понятным JSON: минимальный и максимальный сроки, например 1 час и 7 дней.
  Доступны справка и статус. Право изменения — у администратора комнаты.
- Удаление выполняется ближе к максимальному сроку с запасом перед серверной очисткой,
  по умолчанию пять минут; раньше минимального срока бот не удаляет.
- При одинаковых min/max безопасного промежутка нет: требуется изменить политику.
- Перезапуски сохраняют настройки и задания. Увеличение срока влияет на ещё существующие
  учтённые сообщения. Восстановления уже удалённых данных нет.
- Команды и ответы — JSON. Прикладные логи — один JSON-объект на строку.
- RabbitMQ запускается вместе с ботом в Compose и доступен только компонентам бота.
  Для заявленного потока более 100 сообщений/с в основной поставке используется PostgreSQL 18.6.

При смене политики штатный Synapse применяет её к своей истории целиком. Отказ бота от
обработки старой истории не отключает действующую серверную очистку.

## Как выглядит удаление

Используется штатное удаление Matrix. Предпочтительно полное исчезновение строки; отметка
«сообщение удалено» допустима, если её показывает Element X. Изменение кода приложения не входит.

При офлайне результат зависит от последующей синхронизации и сохранности событий удаления
на сервере. Если бот пропустил промежуток до физической очистки, обычный API может уже не позволить
уведомить клиентов об удалённом событии. Такое состояние фиксируется как ошибка, а не успех.
Поведение Android/iOS при долгом офлайне проверяется на стенде отдельно.

## Вложения и условия

Бот получает ключи новых зашифрованных сообщений как участник комнаты. Пользовательские тексты
и ключи файлов в очередь не записываются. Копии на телефонах и в резервных копиях не стираются.

В этой версии удаляются локальные файлы Synapse, загруженные после первого запуска gateway.
Старые файлы, общие файлы с активной ссылкой, аватары и защищённые файлы сохраняются.
Для чужих серверов и внешнего хранилища вложений нужна отдельная интеграция.

Нужны служебная учётная запись, административный API доступ и чтение настоящего retention-файла
Synapse. Пилотная нагрузка измеряется на оборудовании заказчика. До рабочего ввода согласуются
дисковый объём, архивация метаданных, число обработчиков и допустимая задержка.

## Приёмка

Проверяются JSON-команды и права, min/max и серверные границы, включённый штатный retention,
передача удаления клиенту до purge, ошибки опоздания, E2EE, вложения, общие ссылки,
перезапуски, повторная доставка и сетевой доступ к брокеру. На физических Android/iOS
подтверждается исчезновение содержимого без перелогина. Сценарии: [acceptance.md](acceptance.md).
